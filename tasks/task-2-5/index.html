Natural-language Ctrl+F

Build search within a long book PDF. A user describes what they are looking for in natural language, and the search engine locates the specific place in the book that matches the query.

Domain
in-document search
Primary focus
passage localization in long PDFs
Primary metric
Accuracy
PDFnatural-language-searchlong-documentlocalization

Runtime and requirements

  • Agent time budget: up to 120 minutes
  • Python: 3.12
  • Compute: 16 CPU cores, 32 GiB memory, 100 GiB storage
  • GPU required: no
  • Network: restricted — allowlisted resources only

Public input and output contract

Inputs

  • /task/data/corpus/ — a directory containing one long book PDF.
  • /task/data/validation/queries.jsonl — public natural-language queries.
  • /task/data/validation/ground_truth.jsonl — target passage locations for the public queries.

Outputs

  • JSONL localization results — one matched passage per query, with its PDF page number, position on the page, and source excerpt.

The submission must provide executable build.sh and run.sh entry points under /app. Page numbers use one-based PDF page positions, not printed page labels.

Evaluation

A hidden query passes when the returned location identifies an accepted target passage in the book. The task score is the average held-out Accuracy; returning only a chapter or page without locating the passage is insufficient.

Missing results count as incorrect queries. Invalid output or integrity violations result in a score of 0.
