Introduction to Search-SWE

Search systems are built from connected decisions about data, query understanding, indexing, retrieval, and ranking. Improving one stage can increase memory, storage, or latency elsewhere, so useful systems require engineering across the complete pipeline rather than isolated code changes.

Search-SWE is a benchmark for coding agents that implement and optimize executable search systems under fixed data, interface, compute, and network constraints. It measures whether an agent can turn a specification into a working system and navigate quality-efficiency trade-offs on held-out evaluations.

Two engineering modes

Implementation
Build a working search capability from a task specification.
Optimization
Improve search quality or efficiency within fixed constraints.

How to Contribute to Search-SWE

Open the repository ↗

A task contribution should be a self-contained, reproducible benchmark setting—not only a prompt or dataset. The repository-local create-searchswe-task skill provides the authoring workflow, scaffolder, and validation guidance.

  1. Define the contractChoose Implementation or Optimization, then specify the objective, inputs, outputs, metric, and resource limits.
  2. Build the packageAdd clear instructions, a reproducible environment, fixed and documented inputs, and a meaningful starter for optimization tasks.
  3. Isolate evaluationKeep hidden data and credentials in a separate fail-closed verifier with bounded execution and deterministic gates where possible.
  4. Validate and submitRun static, unit, negative-case, container, and end-to-end checks, then include the evidence and any unrun checks in the pull request.

For concrete package layouts, see Task 1-1 as an Implementation example and Task 2-1 as an Optimization example.

Evaluation

Search-SWE uses Harbor to evaluate coding agents through the supported Codex CLI, Pi, and Claude Code launchers in isolated environments. Agents develop solutions using supplied data and public checks. Submissions are then tested on held-out queries, with task-specific correctness, resource, and integrity checks determining whether their search-quality scores are valid.

Search-SWE evaluation criteria and safeguards
DimensionWhat is checked
Build & functionReproducible execution, valid inputs and outputs, and functional correctness.
Search qualityRetrieval performance on held-out queries using task-specific metrics.
Resource limitsTask-specific time, CPU/GPU, memory, storage, and network constraints.
Evaluation integrityIntegrity and jailbreak checks for attempts to bypass task rules or manipulate evaluation.
