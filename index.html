Search-SWE

Benchmarking coding agents on search-system engineering.

Search-SWE evaluates whether coding agents can implement, optimize, and repair real search systems under fixed resource constraints.

GitHub ↗ Browse tasks →

Overview

Search involves more than choosing a model. Data processing, indexing, retrieval, and ranking must work together within latency, memory, and storage limits.

Three engineering modes

Implementation
Build a search capability from a task specification.
Optimization
Improve an existing system within fixed constraints.
Repair
Diagnose and fix failures in a search system.

Evaluation

Agents develop a solution using the supplied data and public checks. Each submission is then rebuilt in a clean sandbox and tested on hidden queries.

What Search-SWE evaluates
DimensionWhat is measured
Build & functionReproducible builds, required inputs and outputs, and edge cases.
Search qualityRetrieval performance on held-out queries using task-specific metrics.
Resource useCompliance with time, memory, storage, GPU, and network limits.

Results. The leaderboard is being prepared.

Key findings

  • Agents are stronger at locally verifiable repairs than at open-ended search-system design.
  • Combining search components does not ensure agents understand the task objective.
  • Quality, latency, memory, and completeness remain difficult to optimize together.
  • Public checks can encourage heuristic overfitting.
  • Large gains often come from understanding the structure of the data.
