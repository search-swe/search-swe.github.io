Search-SWE

Benchmarking coding agents on search-system engineering.

Search-SWE evaluates whether coding agents can implement and optimize real search systems under fixed resource constraints.

GitHub ↗ Browse tasks →

Overview

Building an effective search system requires coordinating data processing, query understanding, indexing, retrieval, and ranking. Choices at one stage affect the others: richer representations can increase memory and storage costs, while deeper retrieval and reranking can improve relevance at the expense of latency. Search-SWE tests whether coding agents can navigate these trade-offs to build and improve working systems under fixed resource budgets.

Two engineering modes

Implementation
Build a working search capability from a task specification.
Optimization
Improve search quality or efficiency within fixed constraints.

Selected tasks across query understanding, retrieval, ranking, and indexing.

  • Task 1-1 Reasoning-intensive Query Rewriting Rewrite complex biology queries to bridge the gap between query intent and relevant documents. Implementation
  • Task 1-2 Memory-constrained Dense Retrieval Search 1.5M dense vectors within 2 GiB of memory while meeting accuracy and latency requirements. Implementation
  • Task 2-1 Constrained Long-document Reranking Improve long-document reranking through window selection and score aggregation, with a fixed model and candidate set. Optimization
  • Task 2-2 Domain-specific Embedder Fine-tuning Fine-tune a pretrained embedder for code retrieval while preserving its backbone architecture. Optimization
  • Task 2-3 Query-side Encoder Alignment Align a compact query encoder with fixed document embeddings under a runtime constraint. Optimization
  • Task 2-5 Sparse Retrieval Postings Pruning Preserve NDCG and recall while optimizing search time against an unpruned starter. Optimization

Evaluation

Search-SWE uses Harbor to evaluate coding agents such as Codex CLI and Claude Code in isolated environments. Agents develop solutions using supplied data and public checks. Submissions are then tested on held-out queries, with task-specific correctness, resource, and integrity checks determining whether their search-quality scores are valid.

Search-SWE evaluation criteria and safeguards
DimensionWhat is checked
Build & functionReproducible execution, valid inputs and outputs, and functional correctness.
Search qualityRetrieval performance on held-out queries using task-specific metrics.
Resource limitsTask-specific time, CPU/GPU, memory, storage, and network constraints.
Evaluation integrityIntegrity and jailbreak checks for attempts to bypass task rules or manipulate evaluation.
