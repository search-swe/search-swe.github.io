01 · Motivation · Why

Building search is an engineering problem, not a single-model choice.

01

Real systems have many parts

Reliable search requires data inspection, indexing, retrieval, filtering, reranking, interfaces, and validation.

02

Expert choices must be engineered

Agents must turn retrieval knowledge into robust choices about models, tools, data flow, and system constraints.

03

Working systems are the evidence

A plausible plan is not enough. The final artifact must build, run, and produce useful search results.

? THE QUESTION

Can a coding agent build, optimize, and repair a real search system?

02 · Search-SWE · What

A benchmark for coding agents that engineer search systems.

Each task gives an agent a concrete search-system scenario, the relevant assets and constraints, and an executable evaluator for the delivered change.

Search-SWE evaluates coding agents on the practical engineering work behind real search systems.

Its tasks span implementation, optimization, and repair. An agent may need to construct a missing capability, improve a working pipeline under constraints, or identify and fix a broken integration.

CORE PRINCIPLE

Do not score the rationale.
Score the working system.

03 · Task construction · How

Ground each task in a real search-system engineering scenario.

⌁
TASK CONTEXT

Real-world problem

A concrete search-system need: a missing feature, a quality bottleneck, or a faulty production path.

▣
ENGINEERING CONSTRAINTS

Fixed environment

Every agent works with the same data, compute, storage, software, model, and network budget.

✓
EXECUTABLE EVALUATION

Public and hidden checks

Public cases support iteration; hidden checks assess correctness, search quality, and system behavior.

Tasks are organized as implementation, optimization, and repair problems. The homepage highlights six; the catalog contains seven defined scenarios.
